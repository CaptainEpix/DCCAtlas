          Servers

          The file and list servers in your sources' channels, and the lists of what they hold, by source.

          How this works

          Servers are listed as they announce themselves in a source's channel while it is connected; nothing is sent to see them. SysReset's and FServe.pl's announcements are read, and a list server's "@Nick". Ask for lists sends "!list" to the channel, at most once a minute: servers answer with their lists' names, and are listed too. A list a server sends you unasked in the two minutes after is taken, one at a time, and kept as its file list; nothing else is taken.

          Browse sends a file server's trigger once and reads its folders. Get list sends "@Nick" once and keeps the list it sends. A file list is searched under Search without sending anything; before a download the file server is asked for a fresh listing of the file's folder, and a list server's file is asked for by posting its row.

            Lists of removed or changed sources

            Their source was removed, or now names another server, so they cannot be searched.

              Add a list by hand

              Pick the list on this computer, or one already in the downloads folder: a .txt, or a .zip, .rar or .7z holding one. A file sent from here is kept with DCCAtlas's lists in its appdata. A list added by hand does not say whose list it is, so type it in. A list server's list (rows such as !Nick name ::INFO:: size) is recognised by itself and needs no trigger: its files are fetched by posting their rows, as with Get list. For a file server's listing, nothing checks that the list is that server's: a download from it asks the nick typed here, with this trigger, after the usual fresh listing of the file's folder.

                  Apps

                  Prowlarr, and through it Sonarr, Radarr and Readarr, or a book app such as Bindery directly: any app that searches a Newznab indexer and downloads through SABnzbd can use DCCAtlas as both.

                  How this works

                  A search in Prowlarr reaches only the sources whose category it asks for (each source's Category, under Sources), and the stored file lists of such sources; asked for no category, only stored file lists are searched, which sends nothing. A Books search reaches Books, EBook and Comics sources; an EBook search reaches EBook and Books sources. It is one search of those places, with the same limits as a search across sources here. Prowlarr gets an answer within 30 seconds; the search goes on here, and the same search again in Prowlarr shows the rest without sending anything again. A file sent from Prowlarr starts as Download does here, once, and is never asked for again by itself.

                  A source of the category asked for that is not connected is connected for the search, and disconnected again once no search has used it for the minutes set below and no download still needs it. A source you connect or disconnect yourself is left as you set it. A source that fails to connect is not tried again for ten minutes.

                  At most the number of searches set below reach IRC from Prowlarr in an hour. Past it Prowlarr is told the limit is reached, and leaves DCCAtlas alone for an hour; nothing is sent. Searches answered from earlier ones, or from stored file lists only, do not count.

                  In Prowlarr (or another app), add an indexer Generic Newznab with URL http://<host>:<port>/newznab, API path /api and the key below; and a download client SABnzbd with host <host>, port <port>, SSL off, URL base sabnzbd and the same key. <host> is the IP address of the machine DCCAtlas runs on, and <port> the port you open this page on (7744 by default on Unraid). Only for Prowlarr started beside DCCAtlas from this project's Docker Compose file, use host dccatlas and port 8080 instead (its name on their shared network).
